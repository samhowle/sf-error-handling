## 1. Verdict

Not deployable as-is. `sf project deploy start --source-dir force-app` will fail: `FlowFaultService.cls:168` declares a local `String pattern` and `:174` calls `Pattern.compile(pattern)`; Apex resolves the receiver to the local variable, the class does not compile, and the whole core package rolls back. The adapter fails independently: `FlowFaultNebulaLogSinkTest.cls:70` filters SOQL on `LogEntry__c.Message__c`, a Long Text Area, which the compiler rejects. Both are one-line fixes. Before the first deploy that anyone other than you exercises, also close the two contract breaks that matter most in a federal-client setting: `contextDetails` is documented in five places as "never shown to users" but is rendered in the default-on technical-details expander (`FlowFaultService.cls:233`), and the Nebula sink returns `isLogged = true` when Nebula silently drops the entry or the save method lets Roll Back Records erase it (`FlowFaultNebulaLogSink.cls:36-41`). Underlying quality is good: the architecture, the parser (all 12 catalogued shapes re-traced), the never-throws/never-hides design, bulk behaviour, HTML escaping, metadata cross-references and test scaffolding all check out. Defects cluster in four places: code that has never been compiled in an org, Nebula integration assumptions, what the Screen path exposes to end users, and validation gaps in `generate-rules.js`.

`force-app/main/default/classes/FlowFaultService.cls:168,174` · conf 0.92 (3)

#### H2. Nebula sink reports success when Nebula silently drops entries
`nebula-adapter/main/default/classes/FlowFaultNebulaLogSink.cls:36-41` · conf 0.91 (6)

`write()` calls `Logger.newEntry(level, message)`, `addTags`, `setRecord`, `saveLog()` and never checks that anything was buffered or saved. #### H3. `Logger.saveLog()` follows `DefaultSaveMethod__c`, so publish-immediately (DD5) is not enforced
`nebula-adapter/main/default/classes/FlowFaultNebulaLogSink.cls:41`; `force-app/main/default/flows/FlowFaultHandlerScreen.flow-meta.xml:30,53-62` · conf 0.92 (6)

Design decision 5, the class header (lines 6-7), `README.md:16`, `docs/adoption-guide.md:54` and the Screen flow's description and `Roll_Back_Records` description all rely on the log entry surviving Roll Back Records / Custom Error because `LogEntryEvent__e` is publish-immediately. That is true only for `SaveMethod.EVENT_BUS`. The no-arg `saveLog()` resolves to `saveLog(transactionSaveMethodName)`, which is `getUserSettings().DefaultSaveMethod__c` (Logger.cls 89-95, 4034-4036), admin-configurable at org/profile/user level. `SYNCHRONOUS_DML` runs the handler inline with ordinary DML on `Log__c`/`LogEntry__c`; `QUEUEABLE` calls `System.enqueueJob`, also transactional. The Screen flow runs Handle_Fault_Core, then Roll_Back_Records (`:166-173`, `:53-62`, default true), so both methods lose the entry after the sink has returned and `isLogged` is already true. Nothing in the repo mentions SaveMethod; `FlowFaultNebulaLogSinkTest` asserts nothing about it.

Failure: admin sets `DefaultSaveMethod__c = 'SYNCHRONOUS_DML'` (a supported option used to avoid event latency). Screen flow faults; entry inserted; Roll Back Records reverts it; user sees `Reference ID FLT-3F9A2C1B` with `isLogged = true`; support finds nothing. Same for record-triggered flows ending in Custom Error.

Fix: `Logger.saveLog(Logger.SaveMethod.EVENT_BUS);` (applies to that call only; does not alter the transaction default). Add one sentence to `docs/design-decisions.md` §5 and the README caveats. Nebula's shipped default is EVENT_BUS, which is why one verifier rated this medium.

#### H4. `FlowFaultNebulaLogSinkTest` filters SOQL on a Long Text Area; adapter package will not compile
`nebula-adapter/main/default/classes/FlowFaultNebulaLogSinkTest.cls:70` · conf 0.94 (3)

Deploys are atomic, so `sf project deploy start --source-dir nebula-adapter` rejects both the sink and its test. Finder raised as critical; verifiers lowered to high because it is test-only and confined to the optional package directory. It is still a hard deploy blocker for the adapter.

Failure: deploy nebula-adapter to a scratch org with Nebula installed; compile error on line 70; neither class lands; no adapter coverage.

Fix: drop the `Message__c` filter and check `e.Message__c.startsWith('[FlowFault]')` in Apex (test data isolation guarantees only this test's entries exist), or filter on `Log__r.TransactionId__c = :Logger.getTransactionId()`. Do not copy the LIKE pattern into new tests (see L7).
